# スマホ向け画面案
入力: [利用シナリオ](../user-stories/stories.md)、[要件](../requirements-analysis/requirements.md)、[開発方針](../practices-discovery/team-practices.md)、[画面の回答](refined-mockups-questions.md)。
初期ワイヤーフレームはclassicでは対象外のため、上記入力から直接設計した。主催者向けの操作画面で、観客専用画面ではない。

## 構成と見た目
明るい背景 #F8FAFC、白いパネル、濃色文字 #0F172A、青 #1D4ED8 の主要ボタン。スマホを最優先とし、320px幅で左右16px、要素間16px、カード内16px。幅768px以上も同じタブ構成で最大720pxの中央配置とする。通常文字16px、補助14px、残り時間は幅に合わせ56〜80px、等幅数字。ボタン高さ48px、間隔8px以上。

常時上部: 「LTタイマー」とアカウント操作。次に「進行」「設定」の2タブ。選択タブは青い下線と文字で区別。AWSやMQTTの実装用語は通常操作に出さない。

## M1 ログイン
US1.1。見出し「主催者ログイン」、説明「許可された主催者のみ利用できます」、ボタン「ログイン」。認証方式確定後に遷移先を実装する。一般登録のリンクは置かない。
- 読込: 「ログインを確認しています」。
- 失敗: 「ログインできませんでした。もう一度お試しください」＋再試行。
- 権限なし: 「この会場を操作する権限がありません」。ログアウトできる。

US1.3。

| 状態 | 開始前 |
| 大きな時間 | 05:00 |

設定未保存なら時間の代わりに「時間とベルを設定してください」、主操作は「設定する」で設定タブへ移る。設定済みの通知0件なら「ベル通知なし」を明示する。初期値05:00は説明用の例であり保存済みと偽らない。

## M3 進行・実行中
US1.3、US1.4、US1.6、US1.7。
| 上からの順序 | 表示例 |
|---|---|
| 状態と時間 | 実行中 / 03:42 |
| 次のベル | 残り01:00で1回 |
| 主操作 | 一時停止（青・横幅いっぱい） |
| 副操作 | キャンセル（赤い文字の枠ボタン、主操作と16px離す） |
| 通知一覧 | 残り01:00・1回・予定 / 残り00:00・3回・予定 |
| 情報 | 最終更新 14:32:10 |

停止中は状態「一時停止中」、固定した残り時間、主操作「再開」。完了時は「完了 / 00:00」、取消時は「キャンセル済み」。どちらも「同じ設定で開始」を出すが、押した場合にだけ新しい実行を開始する。実行中の設定変更は次回用と明示する。

## M4 設定タブ
US1.2。タブ直下に「次回のタイマー設定」。実行中・停止中なら「変更は次回の開始から適用されます」を常設。
| 順序 | 内容 |
|---|---|
| 時間 | 分 [5] 秒 [00]、説明「1秒〜180分」 |
| ベル | 「残り時間」と「回数」のラベル付き行 |
| 行の例 | 分 [1] 秒 [00] / [1回 v] / 削除 |
| 行の例 | 分 [0] 秒 [00] / [3回 v] / 削除 |
| 追加 | ＋ベルを追加（2/10） |
| 保存 | 設定を保存（青） |
| 結果 | 保存しました / 未保存の変更があります |

回数はネイティブselectで1/2/3回。320pxでは残り時間と回数を2段に折り返し、削除にも「2件目のベルを削除」の名前を付ける。行は残り時間の降順を基本とし、入力中は勝手に移動せず保存成功後に並べ替える。0件は「ベル通知は設定されていません」。10件で追加ボタンを無効化し「最大10件です」。最長は180分00秒で、180分01秒は拒否する。

## M5 取消しの確認
US1.6。見出し「タイマーをキャンセルしますか？」、本文「残り03:42のタイマーと未送信のベル通知を取り消します。送信済みのベルは取り消せません」。ボタン「戻る」「キャンセルする」。初期フォーカスは戻る。送信中は二重実行を防ぎ、結果確定まで閉じて成功扱いしない。

## M6 エラー・部分状態
- 状態取得中: 時間の代わりに「読み込み中」、開始・停止・再開を無効化。
- 通信失敗: 「更新できません。表示は14:32:10時点です」＋「再取得」。既知の時間は表示できるが古い状態であることを常設する。操作は再取得まで無効。
- 入力失敗: 欄直下に「残り時間が重複しています」等の文章。先頭にもエラー件数を示し該当欄へ移動できる。
- 保存失敗: 入力を保持し「保存できませんでした。再試行してください」。
- 競合: 「別の操作で状態が変わりました。最新の状態を確認してください」＋再取得。
- 通知の一部失敗: 各行に送信済み・送信失敗・期限切れ・取消し・結果不明を文字で示す。送信失敗をタイマー停止と混同しない。
- 認証切れ: 「ログインし直してください」。入力下書きは保持し、再認証後にサーバー状態を確認してから操作する。
- エラーをトーストだけに閉じ込めず、その場所に残す。長文は折り返し横スクロールを発生させない。

## 事前接続検証の案内
US1.8の仕様・模擬受信・実機試験は運用手順で提供する。未要求の「今すぐベルを鳴らす」機能や実機の接続ランプは画面に追加しない。近接通知の安全な間隔はデバイス契約で確定し、未確定の間隔を安全と表示しない。
