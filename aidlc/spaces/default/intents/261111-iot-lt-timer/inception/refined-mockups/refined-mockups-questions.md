# 画面案の確認

入力: ../user-stories/stories.md、../requirements-analysis/requirements.md、../practices-discovery/team-practices.md。classicには初期ワイヤーフレームがないため、承認済みの利用シナリオから直接設計する。

確認済み: 日本語、PC・スマホ、320 CSS px対応、キーボード操作、文字で状態を伝える。操作画面と設定保存を提供し、観客専用画面・デバイス状態表示は含めない。
設計の基本: 読込中・空・正常・失敗・一部情報のみの状態を定義する。取消しは確認ダイアログ、入力エラーは欄の近くに表示する。通信暗号化や権限確認はバックエンド側の要件として保持する。

## Q1. 画面構成

A. 1画面に残り時間・操作・設定・通知結果を配置する。PCは2列、スマホは縦並び（推奨）。
B. 「進行」と「設定」をタブで分ける。進行画面に残り時間・操作・通知結果を集める。
X. Other (please specify)

[Answer]: B. スマホで使う想定なので、「進行」と「設定」をタブで分ける。

## Q2. 見た目の方向性

A. 明るい背景、大きな濃色の数字、青系の主要操作。装飾を抑えた実用的な見た目（推奨）。
B. 暗い背景、大きな明るい数字、青系の主要操作。会場でまぶしさを抑える。
C. 既存のロゴ・配色・デザイン規約に合わせる。参照を指定する。
X. Other (please specify)

[Answer]: A. 明るい背景、大きな濃色の数字、青系の主要操作。
