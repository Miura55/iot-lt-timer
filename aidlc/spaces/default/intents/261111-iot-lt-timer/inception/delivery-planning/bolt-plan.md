# 実装・確認の順序

入力: [requirements.md](../requirements-analysis/requirements.md)、[stories.md](../user-stories/stories.md)、[mockups.md](../refined-mockups/mockups.md)、[components.md](../domain-design/components.md)、[unit-of-work.md](../units-generation/unit-of-work.md)、[unit-of-work-dependency.md](../units-generation/unit-of-work-dependency.md)、[unit-of-work-story-map.md](../units-generation/unit-of-work-story-map.md)、[contract-summary.md](../contract-design/contract-summary.md)、[team-practices.md](../practices-discovery/team-practices.md)、[回答](delivery-planning-questions.md)。

「作業単位（Bolt）」は、ここではUnitごとに実装・確認して完了させる一回分のまとまりを指す。依頼者はUnit単位・直列で進め、最初に全体接続を確かめる方針を選択した。順番は承認済みUnitの依存関係に従う。

## Bolt 1 — u1-integrated-timer（歩く骨格）

歩く骨格とは、最初に画面から外部接続までの最小の一連動作を通し、構成がつながることを確かめる実装である。

- **含むUnit**: U1 `u1-integrated-timer`。
- **範囲**: 認証済みの最小ブラウザー画面、時間と通知の入力検証、開始と状態復元、ブラウザーを閉じても続くバックエンド時刻管理、AWS IoT Coreへの送信境界、模擬ベル受信、送信結果の区別。Picoファームウェア自体は依頼者が用意する。
- **完了条件**: 自動テストで認証・入力境界・開始の重複抑止・期限内送信を確認する。模擬受信で通知ID、1/2/3回、0.5秒の打音間隔指定、期限を検証する。ブラウザーを閉じた後もサーバー状態が継続し、再読込で復元できることを結合確認する。AWS資格情報が提供され、接続が許可されている場合はAWS IoT Coreの開発環境へ送信する。模擬試験を実AWSまたは実機確認済みと扱わない。
- **このBoltで確かめること**: バックエンドが時刻管理を担い、AWS IoT経由の命令とベル側の期限・重複排除契約が一連でつながること。
- **デモ**: 主催者がタイマーを開始し、ブラウザーを閉じた後に再度開く。模擬受信の記録で有効な命令と結果を確認する。実機準備後は同じ流れで目視確認する。
- **担当**: AI開発担当（依頼者の作業計画に基づく単独の実装進行）。依頼者はPico側実装と実機試験を担当。

## Bolt 2 — u2-timer-controls

- **含むUnit**: U2 `u2-timer-controls`。U1を維持・拡張する。
- **完了条件**: 一時停止・再開・キャンセル、残り時間の保持、通知世代の更新、送信との競合、結果不明、期限切れ回復を単体・主要境界の結合テストで確認する。送信済み通知を再送せず、停止・取消し受理後の未送信通知を送らないことを確認する。
- **このBoltで確かめること**: APIの冪等性、状態版、通知送信境界を使い、停止・再開・取消しと起床通知の競合を安全に解決できること。
- **デモ**: 実行中に一時停止し残り時間を保持、再開して未送信通知だけを再予定し、最後にキャンセルして未送信通知が無効になることを模擬受信と状態表示で示す。
- **担当**: AI開発担当。

## Bolt 3 — u3-mobile-experience

- **含むUnit**: U3 `u3-mobile-experience`。U1/U2のインターフェースを使う。
- **完了条件**: 「進行／設定」タブ、次回用設定一組の上書き保存、最新版からの開始、320 CSS pxでの主要操作、認証・通信・競合・古い表示・取消し確認、キーボードと読み上げの主要操作を実装・検証する。設定の永続化API、認可、競合処理も含める。
- **このBoltで確かめること**: 共有設定と実行時スナップショットを分離し、スマートフォン中心の操作で誤操作なく準備・進行・再利用できること。
- **デモ**: スマートフォン幅で設定を保存し、進行タブから開始・停止・再開・取消しを操作し、通知結果と最終状態を確認する。
- **担当**: AI開発担当。

## 成功基準

全Unitの受け入れ条件を満たし、単体・主要境界の結合テスト、行カバレッジ80%以上、整形・静的解析とCIを確認する。イベントで使う判断前に、模擬受信と実機確認の証拠を区別して提示する。実機は2026年11月13日までに試せる見込みという回答に基づき計画するが、予定の確約とは扱わない。2秒以内の実機遅れ目標は1/2/3回各10回、計30通知で測り、30件すべてが条件内となることを目標とする。
