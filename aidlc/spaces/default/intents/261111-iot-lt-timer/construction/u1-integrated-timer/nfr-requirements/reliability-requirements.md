# U1 信頼性要件

入力: [U1機能仕様](../functional-design/functional-spec.md)、[U1ルール](../functional-design/rules.md)、[requirements.md](../../../inception/requirements-analysis/requirements.md)、[contract-summary.md](../../../inception/contract-design/contract-summary.md)。

| ID | 要件 | 検証 |
|---|---|---|
| NFR2.1 | 2xxで受理した開始・状態変更は耐久保存後にのみ成功として返し、RPO=0を目標とする。受理済みのsessionId、deadline、通知ID、結果はブラウザー切断や単一実行プロセスの再起動で失わない。 | 永続化直後に実行プロセスを停止・再起動し、同じdeadline・状態・通知結果を復元できるか確認する。 |
| NFR2.2 | 発表時間はサーバーUTC deadlineで進み、ブラウザーのスリープ・終了・時刻変更に依存しない。再接続後はサーバー状態を再取得する。 | ブラウザーを閉じて予定通知と完了を観察する。端末時刻を変更してもサーバー状態は変わらないことを確認する。 |
| NFR2.3 | 起床イベントは重複・早着・順不同・古い世代を許容し、各回で永続状態を再検査する。外部送信と保存の同時原子性は仮定せず、claim・lease・安定IDで回復する。 | 同じ起床を複数回発行、早期／古い世代を発行し、一つの有効な送信だけになることを確認する。 |
| NFR2.4 | 待機登録失敗、期限切れlease、通知0件のdeadline到達を検出し、ブラウザーを開かなくても期限状態が確定する処理を設ける。再照合の起動契機・頻度・遅延上限はFunctional Designの未解決指摘を解消してからコード生成計画に確定する。 | 通知0件、登録失敗、起床消失、lease切れを模擬し、記録に定めた上限以内に回復または明示エラーとなることを確認する。 |
| NFR2.5 | 予定時刻から5秒以上経過した命令は再送しない。期限内の曖昧結果は同じcommandIdで再試行し、期限到達時も曖昧ならunknownを維持する。AWSの受付はデバイス受信・鳴動保証でない。 | 模擬送信の受付、拒否、タイムアウト、再試行中の受付、期限到達を試し状態の最終値を確認する。 |
| NFR2.6 | ブラウザー通信断・認証切れ・AWS障害を成功表示に変えず、最終更新時刻、通知の不明・失敗・期限切れを文字で示す。 | 401、403、429、503、ネットワーク切断、遅延応答を模擬する。 |

数値の可用性SLAは設定しない。初版は単一リージョンでのイベント利用を対象とし、複数リージョン待機や常時運用の保証はしない。通知の送信期限を過ぎた障害では鳴動を追い付かせず、古い命令の再生防止を優先する。イベント前の実機検証と運用可否判断を必要とする。
