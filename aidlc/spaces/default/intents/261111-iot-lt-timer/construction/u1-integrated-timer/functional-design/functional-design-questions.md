# U1 Functional Designの確認事項

## Q1. [運用] MQTT送信結果が不明な場合の再試行
AWS IoT Coreへの送信要求がタイムアウトし、ブローカーが受け付けたか判断できない場合の扱いを決めます。ベル側はcommandIdで重複を抑止し、命令は予定時刻から5秒で期限切れになります。

- A. 同じcommandId・同じ内容で、期限内に限り短い間隔で再試行する。期限まで結果が確定しなければunknownとして記録する。
- B. 再試行せず、すぐunknownとして記録する。重複リスクを避けるが、命令が届いていない可能性が残る。
- C. 別の方針を指定する。
- X. Other (please specify)

[Answer]: A. 同じcommandId・同じ内容で、期限内に限り短い間隔で再試行する。期限まで結果が確定しなければunknownとして記録する。
