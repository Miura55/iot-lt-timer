# U1 拡張・容量設計

入力: [容量要件](../nfr-requirements/scalability-requirements.md)、[機能仕様](../functional-design/functional-spec.md)、[論理コンポーネント](logical-components.md)。

## 初版の容量境界

1会場・ベル1台・同時1セッション・0〜10通知・1〜10800秒に固定する。会場単位の条件付き書込で同時開始を一件に制限し、通知はsessionId/notificationIdから個別に取得できるキー設計とする。プロセス内メモリや単一インスタンスのローカル時計を正本にしない。

API・起床ハンドラーはstatelessとし、共有永続ストアを介して任意の実行インスタンスが処理できるようにする。高可用マルチリージョン、シャーディング、自動スケール閾値、公開マルチテナント負荷は設計・保証対象外。単一会場条件を越える前に会場分離、IoTトピック権限、同時実行制御、費用と負荷試験を再評価する。

費用は具体的なAWSサービス・実行回数・ログ量がInfrastructure Designで定まってから東京リージョンで試算し、月額目安500円と照合する。クレジット前の金額と仮定を提示し、予算超過を自動停止する機能は前提にしない。
